### F1 — the typeface does not survive Resume (HIGH)

| Field | Value |
| --- | --- |
| Where | live production, logged out |
| Repro | Import an image → Create → Text → Font Family = Liberation Mono → click the canvas, type, click away to commit → reload → "Resume editing" |
| Expected | the annotation comes back in Liberation Mono |
| Actual | it comes back in Liberation Sans, and never corrects |
| Screenshot | `qc-screenshots/s4-font-resume-mono-FINDING-sidebyside.png`, `qc-screenshots/s4-font-resume-serif-FINDING.png` |

Measured, same string, same position, full canvas resolution:

| Face committed | Ink width before reload | Ink width after Resume | Reading |
| --- | --- | --- | --- |
| Liberation Mono ("PersistMono") | **137 px** | **117 px** | narrower, proportional letterforms — Sans |
| Liberation Serif ("SerifCheck") | **94 px** | **103 px** | serifs gone — Sans |

Scope, measured rather than assumed:

| Path | Face survives? |
| --- | --- |
| commit → stays in session | **yes** |
| commit → Apply Resize (document re-render) | **yes** (`s2-font-after-resize.png`) |
| commit → reload → Resume editing | **no** |
| after Resume, open the Text panel (registers the fonts) | **still no** — it does not repair |
| Text panel's own Font Family after Resume | resets to "Liberation Sans" |

This contradicts the #131 commit message, which states "After a reload and resume … the face survives persistence."

Hypothesis, offered as a hypothesis and not as a measured cause: `app/src/lib/restoreLayerStack.ts:92` does pass `a.font_id ?? ""` into `restore_text_annotation`, so the id reaches the engine. But `ensureEngineFonts` is only ever reached from `TextSettings.tsx` / `BatchSettings.tsx` (via `useEngineFaces` → `availableFaces`), and nothing on the restore path awaits it. The engine's documented answer for an id it has not been given bytes for is to fall back to the embedded face — pinned by `fonts::tests::an_unregistered_face_falls_back_rather_than_failing`, which passes. In one run the six `.ttf` files had already been fetched by the time I sampled after Resume and the face was still wrong, so this presents as *registration not awaited*, not *fonts never fetched*. Someone who owns the restore path should confirm before fixing.

Not fixed here: the run's stop condition is "any failure is a finding."

### F2 — the Resize panel is seeded with the document, not the photo (MEDIUM)

| Field | Value |
| --- | --- |
| Repro | Import a 1400×900 PNG, look at the status bar and the Resize panel |
| Expected | `Photo: 1400×900`, Resize fields 1400 / 900 |
| Actual | `Photo: 1420×920`, Resize fields **1420 / 920** |
| Duration | polled once a second for **31 s** — never corrected |
| Corrects when | any operation bumps the undo counter (commit a text, apply a resize) — then it reads 1400×900 |
| Second case | a 3000×2000 file (downscaled to 2048×1365 on import) reads `Photo: 2068×1385`; after one undo it reads `2048×1365` |
| Screenshot | `qc-screenshots/s1-image-loaded.png` (status bar bottom right, Resize fields left) |

This is the defect #124 (#81) existed to remove: "a freshly imported 800×600 file read 820×620 and nothing said why" — the comment is still in `StatusBar.tsx:227`. It matters more than a wrong label, because the Resize panel locks its aspect ratio to those fields.

Pre-existing: `usePhotoBounds.ts` was last touched in #159/#124, and neither #131 nor #186 goes near it. Worth noting that the #186 commit message itself describes the test document as "2068 x 1385" — the same stale number.

Hypothesis: the effect in `app/src/hooks/usePhotoBounds.ts` is keyed on `[stampToolRef, revision]`. A ref's identity never changes, so if the effect runs while the worker engine is still starting, it sets `null` and there is no dependency left that can make it ask again. That is the same shape #131's own second commit fixed in `useEngineFaces` — "a ref is not a dependency".

### F3 — a console error on every production boot (LOW)

```
Failed to load resource: the server responded with a status of 404 ()   /_vercel/insights/script.js
Refused to execute script from 'https://edit.imagehorse.app/_vercel/insights/script.js'
  because its MIME type ('text/plain') is not executable
```

`@vercel/analytics` is in the bundle and Web Analytics is not enabled for the project, so the script 404s to the SPA fallback and the browser refuses the HTML as JS. QC §1 asks for a clean boot. Nothing else breaks. Also present in the local build (as a plain 404 + the library's own `[Vercel Web Analytics] Failed to load script` log).

### F4 — focus lands on an invisible control (LOW)

`app/src/features/gallery/GalleryBar.tsx:269` (Remove) and `:279` (Select / Deselect) are styled `opacity-0 group-hover:opacity-100` with no focus variant, and they are tab stops **1 and 2** on a page with a photo loaded. Tab once and the focus ring is drawn on something with zero opacity. WCAG 2.1 AA 2.4.7. Both do carry a `title`, so they are not nameless. Pre-existing.
