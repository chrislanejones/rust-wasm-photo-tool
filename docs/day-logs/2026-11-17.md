## PR 2 — Sending photos, both ways

**This PR**, branch `feat/pair-send`, stacked on **#484** (merge #484 first). OPEN, not merged, nothing deployed.

| Piece | What landed |
|---|---|
| Protocol | `features/pair/photoLink.ts`, pure: manifest → Accept / Decline → files → finished |
| Manifest | device label + per file `name`, `type`, `bytes`, `sha256` |
| Chunks | **16 KB**, one file at a time; send buffer kept under **1 MB** (`bufferedamountlow` at 256 KB) |
| Hash check | receiver checks **SHA-256** (WebCrypto) per file; a mismatch drops that file, the rest go on |
| Cancel / disconnect | Cancel on both sides; disconnect = "Disconnected"; the file in flight is thrown away, checked files stay |
| Limits | **50 MB** a photo, **50** a send, Transfer's image types (reused from `transfer/send.ts`) |
| Limits on the receiver | checked AGAIN: 51 in a manifest = refused whole; a file over the limit = left out with the reason |
| Tier limit | the receiver asks only for what fits, says how many didn't |
| Computer receives | the gallery's own import (`handleAddPhotos`, HEIC Beta included), same as the Inbox |
| Phone receives | MobileShell's own upload; **no engine** |
| Computer sends | **Send to phone** on the gallery: the selection's stored **originals** (or the open photo); "edits aren't included" note |
| Phone sends | **Send photos to computer** on the paired card: the same picker as Send to computer |
| Prompt | "Android phone wants to send 4 photos (18 MB)" → Accept / Decline; progress per photo + overall; Cancel |
| Not built | **Send exported copy**: export runs the engine with per-photo format choices, not cheap to add here |
| Server | **nothing new**. No Convex change, no IndexedDB change, no op-log change, AppShell untouched |
